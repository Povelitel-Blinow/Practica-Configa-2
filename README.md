# Практическая работа №2 — вариант №9

Инструмент построения графа зависимостей пакетов Ubuntu (apt), язык C#.
Выполнены **этапы 1–4 из 5**: конфигурация, сбор данных, построение графа и порядок загрузки.
Граф обходится алгоритмом DFS без рекурсии, с помощью стека.
Используется только стандартная библиотека .NET, без менеджеров пакетов,
сторонних библиотек, LINQ и асинхронного кода.

## Сборка и запуск

Требуется .NET SDK 8. Команды выполняются из корня репозитория.

```powershell
dotnet build src/DependencyVisualizer.csproj
.\run.bat --package bash --repository https://archive.ubuntu.com/ubuntu/ --test-mode false --version 5.2.21-2ubuntu4
```

Запуск без скрипта и справка:

```powershell
dotnet run --project src/DependencyVisualizer.csproj -- --help
```

## Настройки

Все четыре опции обязательны, порядок произвольный. Опция и значение разделяются
пробелом. Пути с пробелами заключаются в кавычки. Повторы и неизвестные опции запрещены.
Относительные пути отсчитываются от текущего рабочего каталога.

| Опция | Значение |
| --- | --- |
| `--package` | Имя apt-пакета: минимум два символа, строчные латинские буквы, цифры, `+`, `-`, `.`; первый символ — буква или цифра. В тестовом режиме — большие латинские буквы, например `A` или `AB`. |
| `--repository` | Абсолютный HTTP/HTTPS URL; в тестовом режиме — путь к файлу графа. |
| `--test-mode` | Только `true` или `false`. |
| `--version` | Версия корневого пакета, например `1.0`, `2:1.0-3`, `1.0~rc1`. В тестовом режиме проверяется формат, но версия не влияет на граф: тестовые вершины версий не имеют. |

`--help` используется отдельно. Пустые и пропущенные значения запрещены.
Версия начинается с цифры (после необязательной числовой эпохи с `:`),
содержит буквы, цифры, `.`, `+`, `~`, `-`; пустые части между дефисами запрещены.

## Этап 3: граф зависимостей (внутреннее представление)

Метод `DependencyGraph.Write` выводит достижимую из указанного пакета часть графа в виде списков
смежности: `пакет: зависимость зависимость`. Пустая правая часть означает отсутствие
зависимостей. Порядок строк соответствует DFS, порядок соседей — исходным данным.
Вершины кладутся в стек в обратном порядке, чтобы первым обходился первый сосед.
Каждая вершина раскрывается один раз. Циклы, включая ссылку на себя, сохраняются
в рёбрах графа и не приводят к бесконечному обходу. Недостижимые вершины не выводятся.
В этапе 4 консольный вывод заменён порядком загрузки, описанным ниже.

### Тестовый репозиторий

Одна строка описывает пакет и его прямые зависимости, разделённые пробелами:

```text
A: B C
B: C
C:
```

Пустые строки разрешены. Имена состоят только из больших латинских букв.
Каждый пакет, включая пакет без зависимостей, должен иметь собственную строку.
Повторное объявление пакета, неверный формат и ссылка на необъявленный пакет
считаются ошибками. Повторы одного ребра удаляются. Проверяется весь файл.

Три примера запуска:

```powershell
.\run.bat --package A --repository tests/fixtures/repository.txt --test-mode true --version 1.0
.\run.bat --package A --repository tests/fixtures/cycle.txt --test-mode true --version 1.0
.\run.bat --package A --repository tests/fixtures/single.txt --test-mode true --version 1.0
```

Ранее первый пример выводил граф выше, а второй — цикл:

```text
A: B
B: C
C: A
```

В этапе 4 эти примеры выводят соответственно `C B A`, `C B A` с предупреждением и `A`.

### Репозиторий Ubuntu

`--repository` принимает прямой URL `Packages` или `Packages.gz`.
Для корня архива используется `dists/noble/main/binary-amd64/Packages.gz`
(Ubuntu 24.04, main, amd64). Другой выпуск, компонент или архитектура задаются
прямым URL индекса. Поддерживаются текст и gzip; `.xz` не поддерживается.

Индекс загружается и разбирается один раз. Для корня выбирается точное совпадение
`Package` и `Version`; для остальных пакетов — первая запись данного имени в индексе.
Рёбра берутся из `Pre-Depends` и `Depends`, включая транзитивные зависимости.
`Recommends` и `Suggests` не включаются.

Это граф возможных зависимостей, а не полный решатель apt: все альтернативы через
`|` включаются в граф; ограничения версий и квалификаторы архитектуры не участвуют
в выборе транзитивных пакетов. Виртуальные пакеты через `Provides` не разрешаются.
Если имя зависимости отсутствует в выбранном индексе, вершина явно помечается
`(нет данных в выбранном индексе)`. Её дальнейшие зависимости неизвестны, поэтому
для таких ветвей граф неполон. Пакет из другого компонента также может получить эту пометку.

## Этап 4: порядок загрузки

После чтения репозитория программа выводит `Порядок загрузки:` и по одному
пакету на строке. Дополнительная опция не нужна: это основной вывод этапа 4.
DFS выполняется без рекурсии. Стек хранит текущий путь, словарь — номер
следующей зависимости, множество — завершённые пакеты. Пакет добавляется
в результат после зависимостей. Корневой пакет тоже включён, повторов нет.
Для графа без циклов каждая зависимость расположена раньше использующего её пакета.
Сложность — O(V + E) по времени, O(V) дополнительной памяти.

При цикле выводится предупреждение: строгого порядка для всех рёбер нет.
Программа пропускает переход к пакету в текущем стеке и выводит порядок
завершения обхода. Это условная последовательность, а не корректная сортировка цикла.
При отсутствии данных о пакете выводятся общая и индивидуальная пометки.
Предупреждения не прерывают работу; код завершения остаётся `0`.

Примеры (в таблице строки результата записаны через пробел):

| Файл из `tests/fixtures` | Результат | Особенность |
| --- | --- | --- |
| `repository.txt` | `C B A` | Транзитивная зависимость |
| `diamond.txt` | `D B C A` | Общая зависимость D один раз; Z недостижима |
| `cycle.txt` | `C B A` | Предупреждение о цикле |
| `self-cycle.txt` | `A` | Предупреждение о ссылке на себя |
| `single.txt` | `A` | Нет зависимостей |

```powershell
.\run.bat --package A --repository tests/fixtures/diamond.txt --test-mode true --version 1.0
.\run.bat --package A --repository tests/fixtures/self-cycle.txt --test-mode true --version 1.0
```

`CheckDownloadOrders` и `CheckOrder` проверяют последовательность, отсутствие
повторов, предупреждения о циклах и неполных данных. Всего проходит 60 проверок.

### Сравнение с apt

В текущей Windows-среде нет apt и установленной WSL, поэтому фактическое
сравнение запусков пока не выполнено. Для проверки в Ubuntu 24.04 с тем же
индексом и доступной версией можно выполнить:

```sh
apt-get -s --no-install-recommends install bash=5.2.21-2ubuntu4
apt-get --print-uris --download-only --no-install-recommends install bash=5.2.21-2ubuntu4
```

Первая команда показывает план установки без изменений системы, вторая —
адреса архивов вместо их загрузки. План установки и порядок скачивания —
разные вещи: наша программа задаёт учебный порядок «зависимости раньше пакета».
Назначение опций описано в [руководстве apt-get](https://manpages.ubuntu.com/manpages/noble/man8/apt-get.8.html).

Ожидаемые причины расхождений: программа не учитывает установленные пакеты,
включает все альтернативы через `|`, не разрешает виртуальные пакеты и не
подбирает версии транзитивных зависимостей. Также используется один индекс,
а apt может работать с несколькими источниками. Независимые пакеты могут
иметь несколько допустимых порядков. Это объяснение ограничений реализации,
а не результат проведённого сравнения с apt.

## Ошибки

Сообщения об ошибках выводятся в stderr, код завершения — `1`.
Успешный запуск и справка возвращают `0`.
Обрабатываются ошибки аргументов, чтения файла, HTTP, формата индекса и gzip.
Тайм-аут получения HTTP-заголовков — 60 секунд.

```powershell
.\run.bat --package "bad name" --repository https://example.org --test-mode false --version 1.0
.\run.bat --package bash --repository bad-url --test-mode false --version 1.0
.\run.bat --package bash --repository https://example.org --test-mode yes --version 1.0
.\run.bat --package bash --repository https://example.org --test-mode false --version latest
.\run.bat --package A --repository missing.txt --test-mode true --version 1.0
```

## Проверки

```powershell
dotnet run --project tests/DependencyVisualizer.Tests.csproj
```

Это консольная программа без тестовых библиотек; `dotnet test` не используется.
Проверки выполняются без сети. Сохранены проверки аргументов и парсера этапов 1–2.
Добавлены пять проверок: DFS с общим потомком и циклом, ссылка на себя,
одиночная вершина, отсутствующая вершина и транзитивный apt-граф с выбором версии.
HTTP-заглушка проверяет полный запуск с текстовым и gzip-индексом.
При ошибке проверки программа возвращает `1`.

## Структура и функции

- `Settings.cs`: четыре параметра запуска.
- `CommandLine.cs`: `Parse` собирает настройки; `ReadOptions` читает пары;
  `Required`, `ValidatePackage`, `ValidateVersion`, `ValidateRepository` проверяют значения.
- `Repository.cs`: `GetIndexAddress` определяет URL; `GetGraph` загружает и распаковывает индекс.
- `PackageIndex.cs`: `ReadGraph` читает записи для графа; `DependencyNames` выделяет имена;
  `ReadRecord` разбирает deb822; `AddDependencies` выделяет группы;
  `Read` сохраняет разбор прямых зависимостей этапа 2 и проверяется тестами.
- `TestRepository.cs`: `Read` читает и проверяет граф; `ValidateName` проверяет имя вершины.
- `DependencyGraph.cs`: `Build` обходит граф стеком; `Write` выводит списки смежности;
  `Nodes` хранит достижимые вершины, `Missing` — имена без данных в apt-индексе.
- `DownloadOrder.cs`: `Build` получает порядок загрузки стеком; `Write` выводит его и предупреждения.
- `Program.cs`: `Main` настраивает консоль; `Run` выбирает источник, строит граф, выводит порядок загрузки и обрабатывает ошибки.
- `tests/Program.cs`: консольные проверки; `Check` сверяет вывод и код завершения,
  `CheckGraphs` проверяет графы, `CheckIndex` — прямые зависимости,
  `CheckIndexError` — ошибки индекса, `CheckOptions` и `CheckValue` — аргументы,
  `CheckTestRepository` — файлы, `ValidArgs` создаёт аргументы, `Assert` учитывает результат.
  `IndexHandler` подменяет HTTP-ответы.
- `tests/fixtures/`: обычный граф, цикл и одиночная вершина.
- `run.bat`: запуск приложения с передачей аргументов.

Этапы 1 и 2 доступны в истории отдельных коммитов. Вывод настроек этапа 1
и вывод только прямых зависимостей этапа 2 заменены выводом графа этапа 3.
Этап 5 (Mermaid) пока не реализован.
Файлы сборки, настройки редакторов, временные файлы и PDF задания исключены через `.gitignore`.
