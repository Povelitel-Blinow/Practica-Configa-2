# Практическая работа №2 — вариант №9

Инструмент визуализации графа зависимостей пакетов Ubuntu (apt), язык C#.
Выполнен **этап 1 из 5: минимальный прототип с конфигурацией**.
Программа принимает опции командной строки, проверяет их и выводит настройки
в формате `ключ=значение`. Получение зависимостей и построение графа относятся к следующим этапам.

Используется обычный C#: классы, методы, циклы, условия и стандартная библиотека.
Сторонних зависимостей, LINQ, асинхронного кода и готового парсера аргументов нет.

## Сборка и запуск

Требуется .NET SDK 8. Команды выполняются из корня репозитория.

```powershell
dotnet build src/DependencyVisualizer.csproj
.\run.bat --package bash --repository https://archive.ubuntu.com/ubuntu/ --test-mode false --version 5.2-2
```

Можно запускать напрямую:

```powershell
dotnet run --project src/DependencyVisualizer.csproj -- --help
```

## Настройки

Все четыре опции обязательны, порядок произвольный. Опция и значение разделяются пробелом.
Пути с пробелами заключаются в кавычки. Повторные и неизвестные опции запрещены.

| Опция | Значение и проверка |
| --- | --- |
| `--package` | Имя apt-пакета: от двух символов, строчные латинские буквы, цифры, `+`, `-`, `.`. |
| `--repository` | Абсолютный HTTP/HTTPS URL; в тестовом режиме — путь к доступному для чтения файлу. |
| `--test-mode` | Только `true` или `false`, в нижнем регистре. |
| `--version` | Числовая эпоха с `:` необязательна; версия начинается с цифры, допускает буквы, `.`, `+`, `~`, `-`. |

Имя обычного пакета должно начинаться с буквы или цифры.
В тестовом режиме имя состоит только из больших латинских букв, например `A` или `AB`.
Версия не может оканчиваться дефисом или содержать пустые части между дефисами.
Примеры версий: `1.0`, `2:1.0-3`, `1.0~rc1`.
`--help` используется отдельно и выводит краткую справку.

На этапе 1 проверяется формат URL, без сетевых запросов и проверки существования пакета или версии.
Тестовый файл открывается для проверки доступа; его содержимое пока не разбирается.
Относительные пути отсчитываются от текущего рабочего каталога.

Пример вывода:

```text
package=bash
repository=https://archive.ubuntu.com/ubuntu/
test-mode=false
version=5.2-2
```

Тестовый режим:

```powershell
.\run.bat --package A --repository tests/fixtures/repository.txt --test-mode true --version 1.0
```

## Ошибки

Ошибка выводится в stderr с указанием проблемной опции. Код завершения — `1`;
при успешном запуске или выводе справки — `0`. Пустые и пропущенные значения запрещены.

Примеры для демонстрации ошибок каждого параметра:

```powershell
.\run.bat --package "bad name" --repository https://example.org --test-mode false --version 1.0
.\run.bat --package bash --repository bad-url --test-mode false --version 1.0
.\run.bat --package bash --repository https://example.org --test-mode yes --version 1.0
.\run.bat --package bash --repository https://example.org --test-mode false --version latest
.\run.bat --package A --repository missing.txt --test-mode true --version 1.0
```

## Тесты

```powershell
dotnet run --project tests/DependencyVisualizer.Tests.csproj
```

Это отдельная консольная программа без тестовых библиотек; `dotnet test` для неё не используется.
Проверяются оба режима, справка, ошибки всех четырёх настроек, пропуски, пустые значения,
повторы, неизвестные опции, путь с пробелами, отсутствующий файл и каталог вместо файла.
Также проверяются коды завершения и разделение stdout/stderr. При ошибке тесты возвращают `1`.

## Структура и функции

- `src/Settings.cs`: класс с четырьмя параметрами запуска.
- `src/CommandLine.cs`: `Parse` собирает настройки; `ReadOptions` читает пары;
  `Required` проверяет наличие; `ValidatePackage`, `ValidateVersion`, `ValidateRepository` проверяют значения.
- `src/Program.cs`: `Main` настраивает консоль, `Run` выводит настройки или сообщение об ошибке.
- `tests/Program.cs`: консольные проверки; `Check` сравнивает вывод и код завершения.
- `tests/fixtures/repository.txt`: пример файла тестового репозитория для запуска.
- `run.bat`: запуск приложения с передачей аргументов.

Файлы сборки, настройки редакторов, временные файлы и локальный PDF с условием исключены через `.gitignore`.
Этап сохраняется отдельным коммитом в формате Conventional Commits.
